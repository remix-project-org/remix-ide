# QuickDApp: Generating UIs for your Contracts

QuickDApp is a feature in Remix IDE that uses AI to generate front-end interfaces for your deployed Solidity contracts. Instead of manually building a UI, you can describe the dApp you want, optionally pointing QuickDApp at a Figma design, and it will generate a ready-to-use React application, either in its own workspace or alongside your contract. It supports both standard web dApps and Base mini apps.

## Creating a dApp

You can create a dApp with QuickDApp from:

1. A deployed contract in the Deploy and Run plugin
2. A `.sol` file
3. A `.subgraph` file or query
4. A Circom circuit (`.circom` file)

```{warning}
The dApps generated by QuickDApp are designed to work on public networks because it deploys the front end code to IPFS. Local networks like the Remix VM will have limited functionality.

```

### Creating a dApp from Deploy and Run

When you compile and deploy a Solidity contract using the Deploy and Run plugin, click the three dots next to the deployed contract and select **Create a DApp**.

![Deployed contract dropdown](images/quickdapp/create-dapp-from-deployandrun.png)

You will be required to answer the following in the RemixAI Assistant or use the defaults provided:

1. **Location**: Workspace (default) or Inline. Inline keeps the dApp beside your contract, which suits iterating on both, but mixes a React app into your Solidity tree. Workspace gives the dApp its own workspace and switches you to it, keeping it self-contained and easier to export. Use Inline while iterating, Workspace to ship.

2. **Base mini-app**: No (default) or Yes. No generates a standard React web dApp; Yes generates a Base mini app. It changes how the project is structured, not just how it looks, so choose correctly the first time.

3. **Design**: Defaults, style notes, or a Figma URL. Defaults give a clean, generic layout. Style notes are free text, so name the colour scheme, light or dark, layout density, and which functions to feature; "make it look nice" gives the AI nothing to act on. Use a Figma URL when you already have a design to match.

4. **Subgraph**: None (default) or a `.subgraph` file path/name. A Subgraph indexes your contract's events, so supplying one optimizes how the dApp retrieves historical data such as past transfers or totals. It must index the contract you are generating for. See {doc}`Subgraphs in Remix </subgraph>`.

After providing all the necessary context for your dApp, hit enter. RemixAI will summarize your answers back to you and ask you to reply **Confirm** to start the generation.

RemixAI then writes the dApp's files, proposing each one for you to approve. You can approve them individually, or use **Approve All** to accept the whole set.

![RemixAI writing the dApp files while the preview prepares](images/quickdapp/quickdapp-start-screen.png)

When generation finishes, the dApp opens in the QuickDApp tab with a live preview of the generated UI.

![Generated dApp preview in the QuickDApp tab](images/quickdapp/quickdapp-finish-screen.png)

From here you can click **View DApp** to open it, **Refresh Preview** to rebuild the preview, **Go to Contract** to jump back to the contract it was generated from (the Primary Contract, if the dApp uses more than one), or **Ask AI to Update** to change the result. **Ask AI to Update** is also where you can upload a reference image and ask the AI to follow it, as there is no image upload among the initial questions. **Delete DApp** removes the generated dApp.

![Annotated QuickDApp toolbar](images/quickdapp/quickdapp-buttons.png)

### Creating a dApp from `.sol` files

When you open a `.sol` file in the Remix IDE, a banner labelled **Create a dApp with your contract** will appear at the top of the editor. To create a UI for the open contract, click **Start now**.

![Start now banner at the top of the editor](images/quickdapp/start-now-banner.png)

When you click **Start now**, QuickDApp checks for deployed instances of the open Solidity file. If there are no deployed instances of the contract, you will be prompted to compile and deploy the contract before clicking **Start now** again.

![Prompt to compile and deploy when no instances are found](images/quickdapp/no-instances.png)

If there is a single deployment of the contract, QuickDApp will prompt you to confirm that you want to create a dApp with the contract. After your confirmation, RemixAI asks you the same questions described above, and generation proceeds the same way.

For cases where more than one deployed instance of the contract exists, you will need to pick the instance you want to create a dApp for before proceeding.

![Selecting from multiple deployed instances](images/quickdapp/multiple-instances.png)

### Creating a dApp from a `.subgraph` file

You can also generate a dApp from a Subgraph query rather than from a contract. In the File Explorer, right-click a `.subgraph` file and select **Create dApp from Subgraph Query**. See {doc}`Subgraphs in Remix </subgraph>` for the full flow.

### Creating a dApp from a Circom circuit

You can also generate a dApp from a ZK circuit rather than from a contract. Once you have compiled your circuit and generated a proof, click **Create ZK DApp** at the bottom of the Circom plugin panel, below the **Generate Proof** button.

![Create ZK DApp button in the Circom plugin panel](images/quickdapp/create-dapp-from-zk.png)

From there, generation proceeds the same way as the other routes. See {doc}`Circom Compiler </circom>` for compiling circuits and generating proofs.

### Creating a dApp from inside another dApp's workspace

You do not have to leave a dApp's workspace to start a new one. While working in an existing dApp's workspace, you can write and deploy another contract, then create a dApp for it from Deploy and Run as usual.

QuickDApp creates the new dApp in a separate workspace of its own rather than inside the current dApp's files. **Go to Contract** in the new dApp takes you back to the workspace the contract was deployed from.

```{note}
Creating a dApp from inside another dApp's workspace only works in Remix on the web, with contracts deployed to a public network such as Sepolia. It is not available on the Remix VM, a local RPC network, or Remix Desktop.
```

## Using multiple contracts

A dApp is not limited to the single contract you generated it from. QuickDApp connects a dApp to its contracts through **contract bindings**: one **Primary Contract** plus up to 7 additional contracts, for a maximum of 8. Bindings only apply to dApps created from contracts, so dApps created from a Subgraph query or a Circom circuit do not have them.

Every contract in a dApp must be deployed on the same network. You can bind several Sepolia contracts together, for example, but you cannot mix a Sepolia contract with one deployed on another network.

### Selecting contracts when you create a dApp

When you create a dApp, the contract you started from becomes the Primary Contract. You can then bind up to 7 more from the contracts already deployed in Deploy and Run.

Decide which contract should be Primary before you start, because the Primary role cannot be moved to a different contract later. Only bind contracts the dApp needs, because bindings cannot be removed once the dApp is created.

### Adding or replacing a contract later

Click **Ask AI to Update** and choose the kind of change you want: updating only the dApp's source, adding a contract, or replacing the contract behind an existing binding. Adding counts toward the limit of 8 contracts, so once a dApp has 8 bindings you can no longer add contracts, only replace existing ones.

Adding and replacing both work from contracts actually deployed in your current Deploy and Run environment, which must be on the same network as the dApp. If it is not, the change is blocked. The contract does not have to come from the dApp's own workspace; you can pick one from any other open workspace. You select the contract and confirm it in the update UI. RemixAI will not take a contract address from your chat message, so pasting an address into the conversation does not bind it.

```{warning}
You cannot add or replace contracts on a dApp built from Remix VM contracts. If you expect to change a dApp's contracts later, deploy them to a public network before creating it.
```

## Generated Workspace structure

When you choose the Workspace location, QuickDApp creates a new workspace named using the pattern `dapp-{contractName}-{id}`. Below is its structure. If you chose Inline instead, these same files are created alongside your contract rather than in a workspace of their own.

```shell
dapp-mytoken-a1b2c3/
├── dapp.config.json
├── src/
├── contracts/
└── preview.png
```

![Generated dApp workspace in the File Explorer](images/quickdapp/quickdapp-workspace.png)

- `dapp.config.json` - Contains the contract address, ABI, and chain ID needed to connect the UI to your deployed contract.
- `src/` - Contains the AI-generated React components, styles, and application logic that make up your dApp's front end.
- `contracts/` - A copy of the Solidity source files used to generate the dApp.
- `preview.png` - A thumbnail screenshot of the dApp, generated automatically when you first preview it.
